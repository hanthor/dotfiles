retired_services

Tags: system, retired_services
Secrets needed: No
Runs on: every systemd host except the vps group and Termux (site.yml gates on vps membership, is_termux and service_mgr)

Deleting a role from the repo stops the fleet from deploying its services, but nothing ever removed what it had already installed — so retired podman quadlets (Prometheus, Grafana, Cockpit, …) kept running on laptops long after their roles were gone (#170). This role removes those leftover unit files.

What It Does

For every unit file in its lists that exists on the machine:

  1. stops the service generated from it — quadlet service names are the file stem (foo.container → foo.service, foo.volume → foo-volume.service, foo.network → foo-network.service); plain .service/.timer files are also disabled
  2. deletes the unit file
  3. runs one daemon-reload (system and/or user, whichever scope had leftovers)

On a machine with none of the files, everything after one find over the unit directories is skipped — the role reports no changes.

Only unit files are removed. Podman volumes (the data of Prometheus, Grafana, NetBox's Postgres, …), images, and config directories such as /etc/cockpit, /etc/homepage, /etc/netbox and ~/.config/monitoring are left alone; delete them by hand once you're sure nothing is wanted (podman volume ls, sudo podman volume ls).

Notes

  • When you delete a role that installed units, add them here in the same PR.
  • User-scope systemctl gets XDG_RUNTIME_DIR=/run/user/<uid> pinned so it works from shells that don't export it.
  • No skip_ flag — the role is a no-op wherever the files are absent.
