# AWS cluster shutdown, 2026-10-25

The AWS Talos cluster, its KubeVirt node and everything on them were shut down
on 2026-10-25 because the account's credits ran out.

## Why

The account ran on **one** credit: *AWS Open Source Promotional Credits*,
issued **$1,435.00**, valid 2026-08-01 to 2028-07-31. It is not monthly. It was
consumed in under three months (Aug $108, Sep $550, Oct $932 applied). October
was the first month with a net bill ($66.15 by the 25th, AWS forecast $307).
At the footprint before the shutdown the cost was about $41/day gross, about
$31/day without the KubeVirt node.

Earlier text in this repo calls the credits "permanent" or "$1400/mo". That was
wrong. $1,400 is the migration budget's ceiling, not an allowance.

## State after the shutdown

| Thing | State |

| `aws-migration-controlplane-hive` (m6i.2xlarge) | stopped |
| `aws-migration-kubevirt` (m7i.2xlarge) | stopped |
| punjab (t3.large, us-east-1) | **running** |
| EBS volumes, snapshots, Elastic IPs | **kept, still billing** |

Matrix (`reilly.asia`), the Hives (`school.`, `reef.`, `hub.tunaos.org`,
`hive.reilly.asia`), the CFP dashboard and Postgres are all offline. Instances
were stopped, not terminated, so disks and their data are intact.

## Where the data is

Bucket `hanthor-fleet-backups-181185361136` (eu-north-1).

| Object | Content |
|---|---|

| `postgres/shutdown-export-2026-10-25/ess_ess-spindle-data.tar.gz` | spindle store (the live homeserver) |
| `…/ess_synapse-media-preseed.tar.gz`, `…/ess_spindle-v0-1-0-rollback.tar.gz` | media, rollback store |
| `…/hive-reef_hive-data.tar.gz`, `…/hive_hive-data.tar.gz`, `…/hive-hanthor_hive-data.tar.gz` | the three Hives' data (about 43 GiB stored) |
| `…/hive_discord-reports-data`, `…/default_review-data`, `…/hive-hub_hive-hub-data`, `…/hive_hive-ops-state` | small state |

All exports are `tar | gzip -1`, storage class `GLACIER_IR`. **Retrieval costs
about $0.03/GB**, so prefer restoring onto the cluster volumes (which still
exist) over downloading.

Each archive was checked for completeness: the tar size recomputed on the node
equals the uncompressed size stored in the gzip trailer.

**Not exported:** contributor homes (`claude-home` 46 GB, `pi-codex-home`
43 GB, `agy-home` 15 GB), the `spindle-rehearsal` volumes, raw `pgdata` (the dump
covers it), `pg-backups` (already in S3), `hive-shared-auth` (provider logins),
and the volumes on the KubeVirt node (monitoring, VM disks, wootc). They remain
on the stopped nodes' disks only.

## Starting it again

Start the control plane first, then the worker, then wait for the nodes to be
Ready. Nothing runs until you scale it back up: every workload was scaled to
zero and its previous replica count written to the annotation
`tunaos.org/pre-shutdown-replicas` (cronjobs were suspended and carry
`tunaos.org/pre-shutdown-suspend=false`).

```bash
export AWS_DEFAULT_REGION=eu-north-1 KUBECONFIG=~/.kube/config-aws-migration
aws ec2 start-instances --instance-ids i-00a3e4532cdbfc87e   # control plane
aws ec2 start-instances --instance-ids i-0bdfafdebc799d49d   # worker (Matrix, Postgres)
kubectl wait --for=condition=Ready node --all --timeout=15m

# Postgres first, then everything else that was recorded.
kubectl -n postgres scale deploy/postgres --replicas=1
kubectl -n postgres rollout status deploy/postgres
kubectl get deploy,sts -A -o json | jq -r '.items[]
  | select(.metadata.annotations["tunaos.org/pre-shutdown-replicas"])
  | "\(.metadata.namespace) \(.kind | ascii_downcase) \(.metadata.name) \(.metadata.annotations["tunaos.org/pre-shutdown-replicas"])"' \
  | while read ns kind name r; do kubectl -n "$ns" scale "$kind/$name" --replicas="$r"; done
kubectl get cronjob -A -o json | jq -r '.items[]
  | select(.metadata.annotations["tunaos.org/pre-shutdown-suspend"] == "false")
  | "\(.metadata.namespace) \(.metadata.name)"' \
  | while read ns n; do kubectl -n "$ns" patch cronjob "$n" -p '{"spec":{"suspend":false}}'; done
```

The KubeVirt node stays stopped. `scripts/kubevirt-node up` starts it; the
node was cordoned (see PR #329), so uncordon it by hand if that script predates
the fix.

Untested: a cold start of Talos from these stopped disks. The stop was a normal
EC2 stop after a clean scale-down.
