# ssh_mesh

`units/ssh-mesh.sh` invokes `units/ssh-fleet.py` under the same SSH lock as [ssh_keys](ssh_keys.md). It skips `machine_profile: vm-test` and `skip_ssh_mesh: true`. It merges valid `machine_pubkeys` from `group_vars/all.yml` into a marked block in `~/.ssh/authorized_keys`, retaining previous managed keys unless explicitly forced and preserving unmarked user and vault entries. It warns if the local public key is missing or stale in git. See [ssh_keys](ssh_keys.md#revoking-access) for revocation, including unmarked legacy entries.

The unit probes online tailnet peers selected by `scripts/online_hosts.py --peers`, intersected with `machines` and excluding the local host, `ssh_mesh_exclude`, inventory VPSes (including nested members), and the retired `matrix` and `telengana` hosts. A host-specific `ssh_mesh_exclude` overrides the group default. It uses effective inventory group and host port, login and tailnet-name overrides and bypasses connection multiplexing. Probes require an independently verified host key with `StrictHostKeyChecking=yes`; missing or changed pins fail closed. On failure it closes an existing mux and retries without modifying `known_hosts`. Persistent failures fail the unit and name the peers.

Normally no vault is needed. If the local identity is missing, the shared implementation consults Bitwarden before restoring or creating it; locked vault or `--no-secrets` defers the identity and probes instead of generating an unmirrored key. Add new public keys to `machine_pubkeys` and host entries to `machines`; configure `tailnet_name` and exclusions where needed.
