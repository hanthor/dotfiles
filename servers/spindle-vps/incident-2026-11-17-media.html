Diagnosing on this host

  • Metrics: docker exec spindle-caddy-1 wget -qO- http://spindle:9100/metrics. spindle_http_requests_total{route="unmatched"} counts paths Spindle does not serve.
  • docker logs spindle-caddy-1 shows nothing new: the container's json log file was deleted from disk. Log to a file in /data instead (above).
  • Editing Caddyfile or spindle.toml: both are single-file bind mounts. sed -i and most editors replace the inode, and the container keeps reading the old file. Write in place (cat new > Caddyfile, or Python open(p, "r+") + truncate), or restart the container. Check with docker exec spindle-caddy-1 cat /etc/caddy/Caddyfile.
  • Seeing what a client requests: sudo tcpdump -i any -A "tcp port 8008 and host <spindle container IP>" shows plaintext proxy→Spindle traffic (it includes bearer tokens; do not save it).
  • Partial-state rooms: docker logs spindle-spindle-1 | grep -E "resync|partial-state".
  • Test account while registration is closed: add shared_secret under [registration], restart, register via /_synapse/admin/v1/register (Synapse HMAC), remove the secret, restart. Details in the Spindle fault guide.

Releasing a Spindle fix to this host

release.yml (dispatch with bump=patch) tags main only after every check on the commit has finished, including the Matrix compliance suite (~1 h after merge). Dispatching earlier logs "CI is still running" or "The Rust quality gate has not passed" and builds nothing. Then:

cd /srv/spindle
cp compose.yaml compose.yaml.bak-pre-vX.Y.Z-$(date -u +%Y%m%dT%H%M%S)
sed -i 's#tuna-os/spindle:vOLD#tuna-os/spindle:vNEW#' compose.yaml   # compose.yaml is not bind-mounted
docker compose pull spindle && docker compose up -d spindle
